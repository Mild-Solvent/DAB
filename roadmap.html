Roadmap

From a friends-only alpha to a network anyone can run.

DAB works today for a small circle of friends. The next steps are to make it safe to hand to strangers, get it into the app stores, and move off borrowed public relays onto a network of small nodes that anyone can run and nobody controls. There are no dates on this page on purpose. Things ship when they are right.

Done In progress Next Later

  1. Where it is today

    0.5 alpha

    A working Android app, sideloaded from this site and updated in place.

    Fog-of-war map Done

    The explored map is stored on your phone only. The trail follows how you move, and offline map areas work with no signal.

    Friends, live and last-seen Done

    Live positions go device to device. A friend who is offline still shows their last known spot from an encrypted event.

    Encrypted chat, files and calls Done

    End-to-end encrypted messages, photos and files, plus audio and video calls. Relayed copies are wiped once the message is delivered.

    Backup, restore, in-app updates Done

    An encrypted backup of your identity and friends, and an update check you can switch off.

  2. 1.0: ready for people we have never met

    In progress

    This is the work that turns an alpha for friends into something you can install from a store and trust.

    A permanent signing key Next

    Alpha builds are signed with a development key. 1.0 moves to a proper release key kept offline. Existing testers get a guided backup, reinstall and restore, so nobody loses friends or chats.

    Final name and app identity Next

    The permanent package name and store listing. A store never lets these change, so they get settled once.

    Delete my data Next

    One button that wipes your keys, friends, chats and explored map from the phone, and withdraws anything still waiting on a relay.

    A plain privacy policy Next

    A short, store-ready policy hosted here that links to the full, code-derived privacy write-up.

    Clear consent for background location Next

    A screen that says exactly what is shared, with whom and how often, before Android asks for the permission.

    Google Play release Next

    A Play build that follows store rules, with updates through Play, fewer permissions and an honest Data Safety form. The sideloaded APK stays available here.

    Automated checks and crash safety Next

    Tests and builds run on every change. When something breaks, the app recovers cleanly and lets you export diagnostics to send yourself. There is no automatic upload.

    Independent security review Next

    Outside eyes on the encryption and relay layer before public users rely on it.

  3. The DAB network

    Designed · prototype running

    Today, messages to an offline friend wait on free public Nostr relays run by strangers. Those relays can go down, see your IP address, and get archived by indexers. The plan is to replace them with dab-node: a small mailbox server anyone can run with one command, joined into an open network with no owner, no accounts and no blockchain.

    dab-node In progress

    It accepts only encrypted DAB messages, refuses to be crawled, and forgets messages once they expire. About 256 MB of disk is enough, so you can drop it on any server you already have and not notice it.

    Mailboxes, not archives Next

    When your friend's phone confirms a message arrived, every node deletes its copy. Nodes only ever hold mail for phones that are offline right now. They never hold a history.

    Open, self-organising network Next

    Nodes find each other without a central list. Each conversation-day lands on a different group of nodes, so no single node ever sees anyone's whole history.

    Built to survive bad nodes Next

    We assume every node is hostile. Messages are stored on several nodes at once, nodes sign what they accept, and phones stop using nodes that lose mail.

    Your IP hidden from the nodes Later

    Requests take two hops. The node that sees your IP never learns which conversations you asked for, and the node that holds them never learns your IP.

    Public relays as a switch Next

    Off, fallback or always. Fallback keeps friends on older versions working during the move, then the default flips to off.

  4. iPhone

    Later

    The app already builds for iOS. What holds it back is that iOS will not let an app listen in the background, and the only way to wake it is Apple's push service.

    TestFlight beta Later

    A signed iOS build in the hands of testers, with calls through the standard iPhone call screen.

    A push service that stores nothing Later

    It sends an empty wake-up and forgets it. The phone then fetches and decrypts the message itself, so content never touches Apple or us. It will be optional, and it will be written up in the privacy document before it ships.

  5. After that

    Later

    Calls that connect everywhere

    Calls on some mobile networks can't reach each other directly. Nodes will be able to offer a relay for them, and until then the app says why a call failed.

    More languages

    Slovak first, then whatever the people using it speak.

    Accessibility

    A full pass with TalkBack and VoiceOver over the map, chat and call screens.

    Polish

    A better image viewer, a tidier chat, faster startup, and backups that carry attachments.

Not on the roadmap

Things we have decided not to build.

Some features would make DAB easier to grow and worse to trust.

  • A blockchain. Nobody needs a permanent copy of a conversation that already lives on two phones. The network deletes messages once they are delivered; it doesn't record them.
  • Accounts. No email, no phone number, no sign-up. Your identity is a key on your phone.
  • Analytics, ads or tracking SDKs. Not now, not in a "free tier", not ever.
  • Public profiles or a stranger map. DAB stays friends-only. You appear only to the people you paired with.

This page describes intent, not promises. Until 1.0, DAB is alpha software that has not had a security review. The install notes say what that means in practice.
